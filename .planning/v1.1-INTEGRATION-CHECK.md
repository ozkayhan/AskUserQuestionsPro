## Verified end-to-end flows

1. **Host ask → lifecycle → durable registration → browser:** host adapters use the shared bridge client; `/ask` registers durable state; `/current`/`/events` expose redacted lifecycle and round identity; the browser consumes the stream.
2. **Browser draft → revision-guarded persistence → reconciliation:** browser draft writer posts `/draft` with capability and revision; Bridge/Record persist the next revision; stale conflicts remain available to explicit reconciliation actions.
3. **Exact recovery selection → server → durable round → browser/host result:** `/rounds` supplies opaque recoverable identities; chooser calls `selectRecoveryRound`; `POST /resume` accepts `{ roundId }`; Bridge finds the exact record and returns the final answers.
4. **Browser answer → immutable result → host response:** `/answer` is capability/revision guarded, finalizes the durable record, and resolves the waiting `/ask` or `/resume` request.
5. **Result delivery → acknowledgement → optional close:** browser posts the durable round acknowledgement before attempting close; retry and uncertain-delivery states remain recoverable. Actual denied `window.close()` behavior is browser-environment limited.
6. **Host detach/restart → adapter resume:** Claude hook and Codex MCP use explicit selectors through `resumeBridge`; fake-host, MCP process-boundary, restart, EOF, idempotency, and long-round tests pass.
7. **Settings schema → persistence → runtime:** shared v2 validation and migration feed atomic/CAS persistence, server injection, CLI doctor/import/export/reset, browser settings, and runtime policy consumers.
8. **Evidence → support claims:** ledger, research records, capability cards, compatibility matrix, OS scenario rows, package/release gates, and docs are validated one-to-one and fail closed when evidence is absent.
