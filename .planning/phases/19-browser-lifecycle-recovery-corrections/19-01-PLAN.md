# Phase 19 Plan: Browser Lifecycle and Recovery Corrections

## Goal

Fix the two reported browser regressions while preserving exact-round recovery:
completed rounds must not leak into a later browser tab, and recovery UI must be
shown only for non-terminal or delivery-uncertain durable records.

## Root Cause Evidence

- `Bridge.listRecoverable()` currently calls `RoundStore.list()`, which includes
  every non-expired record, including `delivered` records.
- `useLiveQuestions()` continues accepting SSE snapshots after a round is
  acknowledged. A completed tab therefore remounts its `Flow` when a later
  round is opened.
- The browser reads the legacy browser settings projection, while the closure
  setting lives in the v2 envelope. The existing `closureMode` check therefore
  never enables the already-supported close attempt.

## Implementation Tasks

### 1. Recovery filtering

- Add a focused regression proving `/rounds` excludes terminal delivered
  records while retaining actual recoverable records.
- Make `Bridge.listRecoverable()` return only states that can be selected by the
  browser recovery flow, including delivery-uncertain result recovery.
- Keep startup hydration restricted to rounds without immutable answers.

### 2. Completed-tab retirement

- Add a pure live-round acceptance/retirement seam and tests for ignoring later
  SSE snapshots after acknowledged delivery.
- Retire the completed tab before a new SSE snapshot can remount its flow.
- Attempt `window.close()` after successful acknowledgement using the v2
  closure setting, while preserving denied-close messaging and uncertain
  delivery recovery.

### 3. Verification and documentation

- Update browser recovery/delivery contract text to describe terminal filtering
  and completed-tab retirement.
- Run focused tests after each red/green cycle, then the full Node test suite,
  ESLint, and Prettier checks.

## Verification Matrix

| Requirement | Verification |
| --- | --- |
| TAB-01 | live/app regression plus `attemptClose`/ack flow test |
| TAB-02 | retired round ignores later SSE snapshot test |
| REC-01 | `/rounds` filtering test for delivered vs recoverable states |
| REC-02 | recovery copy/source contract and existing accessibility tests |

## Risks

- A `delivery-uncertain` record must remain selectable after refresh; filtering
  it out would discard the only visible path to its immutable result.
- Browser close can be denied by the browser, so retirement must prevent a
  denied-close tab from rendering a future round even when the physical tab
  remains open.
