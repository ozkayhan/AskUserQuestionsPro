## Trust Boundaries

| Boundary | Description |
|---|---|
| Runtime output → maintained evidence | Test output can contain payloads, paths, or secrets if not projected/redacted. |
| Package/config checkout → release claim | Published files, dependencies, and protected files determine what can ship. |
| Evidence ledger → host capability status | Missing or unavailable host/OS evidence must not become promotion by omission. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-17-04 | Information Disclosure | `17-VERIFICATION.md`, evidence corpus | high | mitigate | Strict redaction scans and bounded per-label report records reject payloads, secrets, and user paths. |
| T-17-05 | Tampering | package/installer/protected files | high | mitigate | Package allowlist, dependency comparison, isolated scope tests, and baseline-relative protected-file checks. |
| T-17-06 | Elevation of Privilege | host promotion ledger | critical | mitigate | Require installed/authenticated evidence for promotion and retain unavailable external rows as unavailable. |
| T-17-SC | Tampering | package verification | high | mitigate | No installs; package dry-run and zero-production-dependency gates are mandatory. |
</threat_model>
