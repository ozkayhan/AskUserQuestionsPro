# v1.1.1 Release Hardening Audit

## Outcome

The hardening work is locally release-ready, but the milestone is not yet a published npm release. The repository now contains a patch changeset, so the standard GitHub Changesets workflow can perform the authoritative `1.1.0 → 1.1.1` version bump, create the release tag, and publish to npm after the Version Packages PR is merged.

This audit deliberately separates local proof from unavailable external evidence. No unsupported Claude, Codex, Windows, Linux, or assistive-technology claim is promoted.

## Cross-phase integration

The integration checker found 12 connected contracts, 2 partial browser/evidence contracts, and no orphaned application route. Host hook → bridge → browser → answer delivery, MCP → bridge → browser → response, long-round recovery, draft reconciliation, acknowledgement, settings persistence, and local release verification are wired and locally exercised.

The sole release blocker is the package-version checkpoint. This is intentionally resolved through the prepared `.changeset/steady-v11-hardening.md` and the repository's existing GitHub Actions workflow, rather than by publishing from an unauthenticated local npm session.

## Required post-merge handoff

1. Merge this release-hardening PR into `main`.
2. Let `.github/workflows/release.yml` open the Version Packages PR.
3. Merge that generated PR; it will update `package.json`/`package-lock.json` to 1.1.1 and publish/tag through `NPM_TOKEN`.
4. Run the external Phase 15/Windows/Claude/Codex validation lanes when their environments are available.
