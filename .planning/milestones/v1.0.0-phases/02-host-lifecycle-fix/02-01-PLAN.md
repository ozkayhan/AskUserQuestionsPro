# Plan 02-01: Add host liveness and typed lifecycle errors

## Goal

Ensure a long-running MCP tool call emits valid, caller-correlated progress while it waits, and ensure every failure message tells the host/operator whether cancellation, application timeout, or bridge failure ended the round.

## Tasks

<task type="test">
  <name>Define progress heartbeat contract</name>
  <files>test/mcp-progress.test.js</files>
  <action>Write failing node:test cases for valid string/integer progress tokens, strictly increasing progress values, no notifications without a token, and cleanup that stops all future notifications.</action>
  <verify>Run `node --test test/mcp-progress.test.js`; it must fail because the heartbeat module does not yet exist.</verify>
</task>

<task type="implementation">
  <name>Implement zero-dependency heartbeat</name>
  <files>lib/mcp-progress.cjs</files>
  <action>Implement a small injectable-clock heartbeat that emits JSON-RPC `notifications/progress` payloads through a caller-supplied sender, rate-limits with a configurable positive interval, and exposes stop/cleanup. Never log or include question/answer payloads.</action>
  <verify>Run the focused heartbeat tests and inspect notification tokens/progress values.</verify>
</task>

<task type="implementation">
  <name>Wire MCP calls to progress and typed errors</name>
  <files>mcp-server/askuserquestionspro-mcp.mjs; test/mcp-server.test.js; docs/backend.md</files>
  <action>Pass `params._meta.progressToken` into the heartbeat only for active `tools/call` requests. Stop it in `finally`, preserve cancellation semantics, and return distinct actionable text for host cancellation, application timeout, bridge failure, and startup failure. Document that progress is optional host support and does not prove a hard host deadline is absent.</action>
  <verify>Run MCP-focused tests, `npm test`, targeted ESLint, and formatting checks.</verify>
</task>

## Must Haves

- No progress notification is sent without a caller-provided valid token.
- Progress is monotonic and stops after the tool call reaches a terminal path.
- Host cancellation is not mislabeled as a user/application timeout.
- Existing tool result shape remains compatible.
