# Requirements: v1.2.0 Bug Fixes

## Scope

This milestone fixes two browser lifecycle regressions in the existing local single-user bridge. It does not add question types, change host contracts, or broaden recovery beyond the current bridge model.

## Browser Tab Lifecycle

- [x] **TAB-01**: After a round is successfully delivered and acknowledged, the browser tab that owns that round closes automatically.
- [x] **TAB-02**: When a later round is opened after a successful delivery, exactly one browser tab represents the active round; the previously completed tab does not render the new round or create a duplicate.

## Recovery UX

- [x] **REC-01**: The browser shows a local-server recovery prompt only when the current round has a genuine recoverable state, such as an interrupted or detached round that can be resumed.
- [x] **REC-02**: Recovery messaging identifies what happened and offers only actions valid for the current state; normal successful completion and delivery do not produce an unrelated recovery prompt.

## Future Requirements

- Persistent multi-device recovery, remote synchronization, and host-specific recovery policies remain out of scope for this milestone.

## Out of Scope

- Changing the localhost-only security model or adding authentication.
- Removing recovery support; the fix must make existing recovery state-driven and understandable.
- Changing Claude Code or Codex invocation contracts unless required to preserve the browser lifecycle contract.
