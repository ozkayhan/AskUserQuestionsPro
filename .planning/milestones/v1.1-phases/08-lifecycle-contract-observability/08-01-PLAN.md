<feature>
  <name>Deterministic round lifecycle state and ownership contract</name>
  <files>lib/round-state.cjs, server/bridge.js, test/round-state.test.js, test/bridge.test.js</files>
  <behavior>
    - A newly registered round is drafting; host attachment loss transitions it to detached rather than cancelled.
    - Resume exposes reconnecting while an attachment waiter exists; answer acceptance enters delivery-pending, and completion, uncertainty, cancellation, recovery error, and expiry have distinct terminal snapshots.
    - Each public snapshot contains only opaque round identity/capability metadata, state, deadline owner, terminal reason, and timestamps; it contains no questions or answers.
    - A delayed close, duplicate answer, wrong round id, or wrong capability returns a conflict/no-op and leaves the active round unchanged.
    - Injected now/setTimer/clearTimer controls detached expiry deterministically; no state-machine test waits on real time.
  </behavior>
  <implementation>Use Node 18 built-ins only. Keep the existing single-flight Bridge and monotonic numeric id for compatibility, but mint an unguessable per-round capability with node:crypto and make the state module the only source of legal state names, reason normalization, and public projection. Preserve the localhost single-user model; this capability is an ownership guard, not a remote authentication feature. Do not add disk persistence, settings, browser draft storage, or a host-adapter abstraction; those belong to later phases.</implementation>
</feature>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → localhost bridge | A browser submits answer/cancel mutations to the unauthenticated single-user loopback process. |
| host client → localhost bridge | Hook/MCP processes create, detach, and resume host attachments. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | Bridge lifecycle mutations | high | mitigate | Require matching round id and unguessable per-round capability before state mutations; reject stale/delayed operations. |
| T-08-02 | Repudiation | Lifecycle transitions | medium | mitigate | Keep a typed state, terminal reason, and deadline-owner snapshot for each active round. |
| T-08-03 | Denial of service | Detached expiry | medium | mitigate | Use bounded TTL with injected timer ownership and deterministic expiry tests. |
| T-08-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is permitted in this plan; retain zero runtime dependencies. |
</threat_model>
