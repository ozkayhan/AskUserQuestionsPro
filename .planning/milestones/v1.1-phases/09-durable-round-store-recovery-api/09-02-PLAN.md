## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP/host registration to Bridge | Legacy request IDs and question payloads become durable records and browser-visible ownership tokens. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|

| T-09-07 | Spoofing | request ID recovery lookup | high | mitigate | Bind lookup to exact durable ID or a unique request ID plus existing ownership material; report ambiguity explicitly. |
| T-09-08 | Repudiation | final result and delivery acknowledgement | medium | mitigate | Persist immutable result, acknowledgement timestamp, and revision before returning a success response. |
| T-09-09 | Denial of service | restart hydration and expiry | medium | mitigate | Hydrate valid records independently, bound retention from detached TTL, and clean only owned expired records. |
| T-09-10 | Information disclosure | bridge snapshots | medium | mitigate | Keep full record access internal and retain redacted lifecycle projection behavior from Phase 8. |
</threat_model>
