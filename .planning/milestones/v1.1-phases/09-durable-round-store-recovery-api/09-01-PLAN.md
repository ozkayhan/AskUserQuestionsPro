<interfaces>
From lib/atomic-write.cjs: `writeFileAtomic(file, data)` is the existing synchronous lock-and-rename persistence seam. Preserve its fail-fast ownership behavior while adding the durable file-sync and mode guarantees required by the new store.

From lib/round-state.cjs: `createRecord({ id, capability, now, deadlineOwner })`, `transition(record, event, options)`, and `snapshot(record)` define the current lifecycle vocabulary. The durable record must preserve this lifecycle state without duplicating incompatible transition rules.

From server/bridge.js: `DEFAULT_DETACHED_TTL_MS` is the compatibility default; bridge construction resolves `ASKUSER_DETACHED_ROUND_TTL_MS` before passing its detached TTL. The durable store receives that resolved value rather than introducing another environment setting.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bridge to local filesystem | Authoritative question, answer, capability, and lifecycle data crosses from process memory into private snapshots. |
| Persisted file to recovery loader | Disk content may be partial, malformed, stale, or locally altered before it is hydrated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | `lib/round-record.cjs` revision transitions | high | mitigate | Validate opaque IDs and expected revisions; preserve immutable identity/questions/final answers; return typed conflicts. |
| T-09-02 | Information disclosure | `lib/round-store.cjs` filesystem layout | high | mitigate | Request 0700 store directories and 0600 snapshots/temp files; never log serialized record payloads. |
| T-09-03 | Denial of service | startup scan and corrupt files | medium | mitigate | Validate/quarantine one record at a time and continue listing healthy snapshots. |
| T-09-04 | Repudiation | snapshot mutations | medium | mitigate | Persist revision, timestamps, lifecycle state, and acknowledgement fact before success is exposed. |
| T-09-05 | Denial of service | storage write failures | medium | mitigate | Inject and surface write/sync/rename/lock failures; preserve prior named snapshot and prohibit browser-authority fallback. |
</threat_model>
