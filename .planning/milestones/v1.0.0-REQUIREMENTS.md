# v1.0.0 Requirements Archive

All v1 requirements were completed and validated during the milestone. The 27 requirements below retain their original identifiers and outcomes.

## Timeout and Observability

- [x] TIME-01 — Codex 15-question round survives the observed host boundary and resumes exact answers within bounded TTL.
- [x] TIME-02 — Claude hook wire path completes an equivalent round and preserves native fallback; full model session was environment-limited by authentication.
- [x] TIME-03 — Lifecycle logs distinguish host, HTTP, bridge, browser, application-timeout, and process-exit outcomes without question/answer payloads.
- [x] TIME-04 — Failed host connections produce clear recoverable diagnostics.

## Host Integrations

- [x] HOST-01 — Codex MCP `ask` contract remains compatible with the long-round lifecycle fix.
- [x] HOST-02 — Claude native hook fallback contract remains compatible with shared lifecycle semantics.
- [x] HOST-03 — Host failure/cancellation leaves documented actionable fallback guidance.

## Bridge and Server Reliability

- [x] BRDG-01 — Round ownership is checked at resolve, cancel, disconnect, and reconnect boundaries.
- [x] BRDG-02 — User, host, browser, timeout, and bridge terminal outcomes are distinct and idempotent.
- [x] BRDG-03 — Stale/mismatched answers cannot resolve later rounds and return deterministic conflicts.
- [x] BRDG-04 — Dropped `/ask` connections cannot cancel newer rounds or create unbounded orphans.
- [x] BRDG-05 — Localhost-only single-flight behavior remains safe across daemon races and restarts.

## Browser Interaction and Accessibility

- [x] WEB-01 — Long-round navigation, review, and answer state remain consistent.
- [x] WEB-02 — SSE reconnect behavior is bounded, observable, and round-safe.
- [x] WEB-03 — Timeout, disconnect, and server errors are distinct actionable UI states.
- [x] WEB-04 — Existing typed questions, keyboard behavior, review flow, and accessibility semantics remain intact.
